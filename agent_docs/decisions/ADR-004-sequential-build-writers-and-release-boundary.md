# ADR-004: Keep Build writers sequential and publication explicit\n\n**Date:** 2026-09-11\n**Status:** Accepted\n**Deciders:** Repository owner and Codex\n**Supersedes:** The independent worktree-writer sentence in ADR-003; ADR-003 remains historical.\n\n## Context\n\nCodexicon's current `AGENTS.md`, autonomous-build skill, and task register require one primary checkout and one implementation writer at a time. ADR-003 describes independent writers in managed worktrees, which is a contradictory operating instruction for the supported template workflow.\n\n## Decision\n\nBuild uses one sequential writer in the current checkout. Read-only research and review may run independently. A bounded implementer may write one selected task only when the primary agent owns the scope, rereads the changed paths, and performs integration and final verification. Worktrees, staging, commits, pushes, pull requests, releases, deployments, and external writes remain Ship actions requiring explicit authority.\n\n## Rationale\n\nThe rule matches the current shared-checkout implementation, reduces accidental concurrent edits, and keeps the authority boundary understandable to new users. It is reversible if measured evidence later shows that isolated worktrees materially improve quality without confusing the workflow.\n\n## Consequences\n\n- **Positive:** one visible owner, simpler task evidence, fewer merge conflicts, and a clear Build-to-Ship handoff.\n- **Negative:** independent implementation work is serialized and may take longer for large changes.\n- **Review signal:** live paired evaluations should measure whether the quality and coordination tradeoff remains favorable.\n\n
