# ADR-008: Complete adoption workflow

- Date: 2026-11-21
- Owner: bnet47 / Codex
- Status: Accepted
- Evidence: Athlete installation had six project skills while the clean starter has 23; the prior doctor returned no warnings. See the November 21 repair plan and A-043 regressions.
- Decision: Carry all starter skill assets in adoption with conflict-preserving merge policy. Warn about absent core workflow files and an absent operating-guidance reference; document deliberate integration of project-owned AGENTS.md.
- Rationale: Adoption should provide the same portable skills without replacing application instructions or commands. A reference is an integration hint, not measured model compliance.
- Alternatives: Overwriting AGENTS risks losing project rules; requiring SPEC/TASKS for all diagnostics incorrectly rejects uninitialized starters; leaving the six-skill subset silently omits advertised workflows.
- Impact: More absent files appear in update plans; existing customized files and local deletions remain protected. Structural doctor health remains distinct from application verification and live agent behavior.
- Supersedes: None.
